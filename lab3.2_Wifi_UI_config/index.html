การสร้าง Captive Portal Web Dashboard สำหรับตั้งค่า Wi-Fi ลงใน LittleFS พร้อมโหมดแสดงผล Debug บนจอ OLED และปุ่ม Reset GPIO 0

วัตถุประสงค์การเรียนรู้

  • เข้าใจสถาปัตยกรรม Captive Portal และการสลับโหมดระหว่าง Access Point (AP) และ Station (STA)
  • สามารถบันทึกและโหลดการตั้งค่าเครือข่ายลงในไฟล์ /config.json ผ่านระบบไฟล์ LittleFS
  • สามารถสร้าง Web API: /api/scan (สแกนหาเครือข่าย) และ /api/save (บันทึกรหัสผ่าน Wi-Fi)
  • สามารถแสดงผล Debug Mode บนจอ OLED SSD1306 (I2C):
    • โหมด AP: แสดงชื่อ Hotspot SSID และ IP: 192.168.4.1
    • โหมด STA (ต่อสำเร็จ): แสดง SSID, IP, และความแรงสัญญาณ RSSI (dBm)
  • สามารถเขียนโปรแกรมดักจับการกดปุ่มทางกายภาพ GPIO 0 ค้างไว้ 3 วินาที (Long-Press) เพื่อล้างค่า Wi-Fi และเข้าสู่โหมดตั้งค่าใหม่

เนื้อหาทฤษฎี: Web Wi-Fi Provisioning, OLED Debug & Event-Driven Reconnect

1.1 สถาปัตยกรรม Captive Portal & DNS Redirection

Captive Portal เป็นเทคนิคที่นิยมใช้ในการตั้งค่าอุปกรณ์ IoT เมื่ออุปกรณ์ยังไม่มีการเชื่อมต่อเครือข่ายหลัก บอร์ดจะเปลี่ยนตัวเองเป็น Access Point (SoftAP) ที่ IP 192.168.4.1 และเปิดบริการ DNS Server บนพอร์ต 53 ซึ่งจะคอยดักจับคำขอทดสอบอินเทอร์เน็ตของสมาร์ตโฟน (เช่น connectivitycheck.gstatic.com หรือ captive.apple.com) แล้วตอบกลับด้วย IP ของตัวเอง ทำให้ระบบปฏิบัติการมือถือเปิดหน้าต่าง Web Dashboard ขึ้นมาให้ผู้ใช้กรอกรหัสผ่าน Wi-Fi ทันที

Smartphone Client --- [ DNS Query: any domain ] ---> ESP32 DNS Server (Port 53)
Smartphone Client <-- [ DNS Answer: 192.168.4.1 ] --- ESP32 DNS Server
Smartphone Client --- [ HTTP GET / ] ---> ESP32 Web Server (Port 80)

2.1 การจัดเก็บการตั้งค่าแบบ Non-volatile ด้วย LittleFS

การใช้ระบบไฟล์ LittleFS เก็บข้อมูลในไฟล์ /config.json ช่วยให้เราบันทึกข้อมูลชื่อเครือข่าย รหัสผ่าน หรือค่าคงที่อื่นๆ ได้อย่างยืดหยุ่นในรูปแบบ Key-Value โดยข้อมูลจะไม่สูญหายเมื่อตัดไฟเลี้ยง และปลอดภัยกว่า EEPROM ดั้งเดิมเพราะ LittleFS มีระบบ Wear Leveling กระจายการเขียนยืดอายุชิป Flash

3.1 การแสดงผล OLED Debug Display & การกดปุ่ม Reset

จอแสดงผล OLED SSD1306 (I2C 0x3C) ทำหน้าที่เป็นหน้าจอ Debug กึ่งเรียลไทม์:

  • เมื่ออยู่ในโหมด AP: แสดงข้อความ [AP Mode] พร้อมชื่อ SSID ESP_WiFi_Config และ IP 192.168.4.1 เพื่อให้ผู้ใช้ทราบว่าต้องต่อ Wi-Fi อะไร
  • เมื่อเชื่อมต่อสำเร็จ (โหมด STA): แสดงข้อความ [STA Online] พร้อมชื่อ SSID เครือข่าย, หมายเลข IP ที่ได้รับจาก Router และค่าความแรงสัญญาณ RSSI (dBm)
  • เมื่อกดปุ่ม GPIO 0 ค้าง 3 วินาที: จอ OLED จะแสดงผล >> FACTORY RESET << และสั่งลบ /config.json ก่อนรีสตาร์ต

4.1 สถาปัตยกรรม Event-Driven Auto-Reconnect & 30s Auto-Fallback

เมื่อสัญญาณ Wi-Fi หลุดขณะทำงาน ระบบจะใช้ Event Handler (เช่น WiFi.onEvent หรือ WiFiEventHandler) สั่ง WiFi.reconnect() ใน Background Task ทันทีโดยไม่บล็อก Main Loop

ระบบ 30-Second Auto-Fallback: หากเราเตอร์ดับเป็นเวลานานเกิน 30 วินาที ระบบจะสลับเข้าสู่โหมด startConfigPortal() เปิด Hotspot ใหม่อัตโนมัติ เพื่อให้ผู้ใช้สามารถเชื่อมต่อเข้ามาเปลี่ยนรหัสผ่าน Wi-Fi ได้ทันทีโดยไม่ต้องกดปุ่ม Reset กายภาพ

5.1 โครงสร้าง Payload การบันทึกค่า Wi-Fi และคำสั่ง Serial Debug

เมื่อผู้ใช้กดบันทึกข้อมูลในหน้าตั้งค่า Captive Portal หรือส่งผ่าน REST API / Serial Input โครงสร้างข้อมูลที่ใช้มีดังนี้:

ช่องทางการส่ง ข้อความหรือ Payload ที่ต้องพิมพ์ ผลลัพธ์บนไมโครคอนโทรลเลอร์
HTTP POST /api/save {"ssid": "MyWiFi_2.4G", "pass": "secret1234"} บันทึกลง /config.json ใน LittleFS แล้วสั่งรีสตาร์ตเพื่อเกาะเราเตอร์ใหม่
HTTP GET /api/scan (เรียกผ่านบราวเซอร์/Fetch) ส่งคืนอาร์เรย์ JSON: [{"ssid":"WiFi_1","rssi":-65}]
Serial Command (115200) FACTORY_RESET ลบไฟล์ /config.json และสั่ง ESP.restart() ทันที
