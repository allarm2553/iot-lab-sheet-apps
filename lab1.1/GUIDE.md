# 🔘 ใบงานที่ 1.1: การควบคุมเอาต์พุตด้วยอินพุตสวิตช์ปุ่มกด (Digital Inputs & Debouncing)

คู่มือการทดลองเชื่อมต่อสวิตช์ปุ่มกด (Push Button) กับไมโครคอนโทรลเลอร์ ESP32 / ESP8266 พร้อมเทคนิคการป้องกันการสั่นของหน้าสัมผัส (Software Debounce) และการตรวจจับการกดค้าง (Long Press)

---

## 🎯 วัตถุประสงค์ (Objectives)

1. เข้าใจวงจรและความสำคัญของตัวต้านทานพูลอัปภายใน (**Internal Pull-up Resistor**) และภาวะสัญญาณลอย (**Floating State**)
2. เข้าใจปัญหาการกระดอนของหน้าสัมผัสเชิงกล (**Contact Bounce**) และสามารถเขียนโค้ดแก้ปัญหาด้วยซอฟต์แวร์ (**Software Debounce**) ผ่านฟังก์ชัน `millis()`
3. สามารถเขียนโปรแกรมสลับสถานะการทำงาน (Toggle State) ของรีเลย์พัดลมและปั๊มน้ำด้วยการตรวจจับขอบสัญญาณ (**Edge-Triggered**)
4. สามารถเขียนโปรแกรมตรวจจับการกดปุ่มค้าง (**Long Press Detection**) เพื่อรีเซ็ตสถานะระบบอย่างปลอดภัย (Safe State Reset)

## 🛠️ ตารางการตรวจวินิจฉัยและแก้ปัญหา (Troubleshooting Matrix)

| อาการที่พบ (Symptom) | สาเหตุที่แท้จริง (Root Cause) | แนวทางแก้ไข (Solution) |
| :--- | :--- | :--- |
| **สวิตช์ติดๆ ดับๆ สลับสถานะเองแม้ไม่ได้แตะ** | ไม่ได้เปิด Pull-up (ใช้ `pinMode(pin, INPUT)` ธรรมดา) ทำให้ขาอยู่ในสถานะสัญญาณลอย (Floating State) | แก้ไขเป็น `pinMode(pin, INPUT_PULLUP);` |
| **กดปุ่ม 1 ครั้ง แต่วงจรนับว่ากด 2-3 ครั้ง** | เกิดการสั่นของหน้าสัมผัสโลหะ (Mechanical Contact Bouncing) | เพิ่มกลไก Debounce ด้วย `millis()` โดยกำหนด `debounceDelay = 50ms` |
| **ใช้ `delay(50)` แล้วระบบหน่วง หรือ WiFi หลุด** | คำสั่ง `delay()` เป็นแบบ Blocking หยุดการทำงานของ CPU ทั้งหมด | ปรับใช้ Non-blocking Timer ด้วย `millis()` เพื่อให้ซีพียูทำงานอื่นควบคู่ได้ |
| **กดปุ่มค้างแล้วระบบรันคำสั่ง Reset ซ้ำๆ วนลูป** | ขาดตัวแปร Lock Flag ในขณะที่กดค้าง | เพิ่ม `bool longPressTriggered = true;` เมื่อรันคำสั่งแล้ว และรีเซ็ตเป็น `false` เมื่อปล่อยปุ่ม |

## ✍️ เฉลยคำตอบในใบงาน (Worksheet Answers)

### 1. โค้ดเติมช่องว่าง (Code Blanks)
* **ช่องที่ 1 & 2:** กำหนดโหมดพินสวิตช์และรีเลย์:
  ```cpp
  pinMode(BUTTON_PIN, INPUT_PULLUP);
  pinMode(RELAY_PIN, OUTPUT);
  ```
* **ช่องที่ 3 & 4:** ตรวจจับเมื่อมีอีเวนต์กดปุ่มลง และสลับสถานะ:
  ```cpp
  if (currentButtonState == LOW) {
    relayState = !relayState;
    digitalWrite(RELAY_PIN, relayState);
  }
  ```
* **ช่องที่ 5:** สั่งปิดรีเลย์เมื่อกดค้าง:
  ```cpp
  digitalWrite(RELAY_PIN, LOW);
  ```

### 3. คำถามท้ายการทดลอง & การวิเคราะห์ข้อผิดพลาด (Review Questions)

**คำถามที่ 1: [Spot the Bug: Floating Input] นักศึกษาคนหนึ่งเขียนโค้ด `pinMode(BUTTON_PIN, INPUT);` โดยต่อสวิตช์ปุ่มกดระหว่าง GPIO 0 กับ GND โดยตรง พบว่าสถานะพัดลมสลับเปิด-ปิดเองอย่างรวดเร็วแม้มือไม่ได้สัมผัสปุ่ม จงวิเคราะห์ว่าเกิดจากสาเหตุใด และต้องแก้ไขโค้ดอย่างไร?**
> **แนวคำตอบ:** 
> - **สาเหตุ:** การประกาศขาเป็น `INPUT` ธรรมดาโดยไม่มีตัวต้านทานต่อดึงแรงดันภายนอก จะทำให้ขาพินลอยอยู่ในอากาศ (**Floating State**) ซึ่งมีความต้านทานอินพุตสูงมาก ทำให้ไวต่อสัญญาณรบกวนทางแม่เหล็กไฟฟ้า (Electromagnetic Interference) จากอากาศ สัญญาณจึงแกว่งขึ้นลงระหว่าง 0V และ 3.3V สลับไปมาจนไมโครคอนโทรลเลอร์ตรวจจับว่ามีการกดปุ่ม
> - **วิธีแก้:** เปลี่ยนโหมดขาเป็น `pinMode(BUTTON_PIN, INPUT_PULLUP);` เพื่อเปิดใช้งานตัวต้านทานดึงแรงดันภายในชิปเข้าสู่ 3.3V

**คำถามที่ 2: [Debounce Architecture: Non-blocking vs Blocking] จงเปรียบเทียบความแตกต่างระหว่างการแก้ปัญหา Bouncing ด้วยคำสั่ง `delay(50)` กับการใช้ตัวจับเวลา `millis()` ในแง่ประสิทธิภาพของระบบ IoT ที่ต้องรับส่งข้อมูลผ่าน WiFi ตลอดเวลา?**
> **แนวคำตอบ:** 
> - การใช้ `delay(50)` เป็นแบบ **Blocking Call** ซึ่งทำให้ CPU หยุดรอและไม่สามารถประมวลผลงานอื่นได้ ส่งผลให้ Stack เครือข่ายของ WiFi/MQTT ขาดการตอบสนอง และอาจทำให้เกิด Watchdog Reset
> - การใช้ `millis()` เป็นแบบ **Non-blocking Timer** ซึ่งใช้วิธีเปรียบเทียบเวลาส่วนต่าง ทำให้ CPU สามารถวนลูปทำงานอื่น เช่น การอ่านเซ็นเซอร์ การส่งข้อมูลขึ้นคลาวด์ ได้อย่างราบรื่นและตอบสนองได้ทันที

**คำถามที่ 3: [Fail-Safe & Edge-Triggered State Machine] เหตุใดในระบบควบคุมทางอุตสาหกรรม การสั่งงานด้วยปุ่มกดจึงต้องใช้การตรวจจับขอบสัญญาณ (Edge-Triggered) แทนการตรวจจับระดับสัญญาณ (Level-Triggered) และการกดปุ่มค้าง 2 วินาทีเพื่อ Reset ช่วยป้องกันอุบัติเหตุได้อย่างไร?**
> **แนวคำตอบ:** 
> - **Edge-Triggered:** ทำงานเฉพาะจังหวะเปลี่ยนสถานะ (เช่น กดลง 1 ครั้ง = สลับสถานะ 1 ครั้ง) ต่างจาก Level-Triggered ที่หากตรวจพบว่าปุ่มเป็น LOW ระบบจะสั่งสลับสถานะรัวๆ ตลอดเวลาที่ยังกดอยู่
> - **Long Press 2 วินาที:** ช่วยป้องกันความผิดพลาดจากการเผลอไปโดนปุ่มโดยไม่ตั้งใจ (Accidental Touch) ทำให้มั่นใจว่าผู้ปฏิบัติงานมีความตั้งใจที่จะสั่ง Reset หรือหยุดระบบฉุกเฉินจริง

## 🏆 โจทย์ท้าทายการทดลอง (Lab 1.1 Challenge)

เขียนโค้ดภาษา C++ ปรับปรุงตรรกะในฟังก์ชัน `loop()` ให้มีคุณสมบัติต่อไปนี้ครบถ้วน:
1. **Toggle Count:** นับจำนวนครั้งการกดสวิตช์สลับสถานะ Relay 1 (พัดลม)
2. **Mist Relay Trigger:** เมื่อกดสวิตช์ครบ 3 ครั้ง ให้เปิดการทำงานของ Relay 2 (ปั๊มพ่นหมอก - GPIO 23)
3. **Long Press Reset:** เมื่อกดปุ่มค้างไว้นานกว่า 2 วินาที ให้สั่งปิดดับรีเลย์ทั้งสองตัวพร้อมกันทันที (Safe State) และรีเซ็ตตัวนับเป็น 0 พร้อมส่งข้อความแจ้งเตือนทาง Serial Monitor
