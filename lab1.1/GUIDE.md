# 🔘 ใบงานที่ 1.1: การควบคุมเอาต์พุตด้วยอินพุตสวิตช์ปุ่มกด (Digital Inputs & Debouncing)

คู่มือการทดลองเชื่อมต่อสวิตช์ปุ่มกด (Push Button) กับไมโครคอนโทรลเลอร์ ESP32 / ESP8266 พร้อมเทคนิคการป้องกันการสั่นของหน้าสัมผัส (Software Debounce) และการตรวจจับการกดค้าง (Long Press)

---

## 🎯 วัตถุประสงค์ (Objectives)

1. เข้าใจวงจรและความสำคัญของตัวต้านทานพูลอัปภายใน (**Internal Pull-up Resistor**)
2. เข้าใจปัญหาการกระดอนของหน้าสัมผัสเชิงกล (**Contact Bounce**) และสามารถเขียนโค้ดแก้ปัญหาด้วยซอฟต์แวร์ (**Software Debounce**) ผ่านฟังก์ชัน `millis()`
3. สามารถเขียนโปรแกรมสลับสถานะการทำงาน (Toggle State) ของรีเลย์พัดลมและปั๊มน้ำด้วยการกดปุ่ม
4. สามารถเขียนโปรแกรมตรวจจับการกดปุ่มค้าง (Long Press Detection) เพื่อรีเซ็ตสถานะระบบ

### 1. โค้ดเติมช่องว่าง (Code Blanks)
* กำหนดโหมดพินสวิตช์และรีเลย์:
  ```cpp
  pinMode(BUTTON_PIN, INPUT_PULLUP);
  pinMode(FAN_RELAY_PIN, OUTPUT);
  ```
* ตรวจจับการกดปุ่ม (Active LOW) และสลับสถานะ:
  ```cpp
  if (currentButtonState == LOW) {
    relayState = !relayState;
    digitalWrite(FAN_RELAY_PIN, relayState ? HIGH : LOW);
  }
  ```

### 2. คำถามสรุปผลการทดลอง (Review Questions)

**คำถามที่ 1: วงจร `INPUT_PULLUP` มีการต่อวงจรและให้สถานะทางลอจิกขณะยังไม่กดปุ่ม และขณะกดปุ่มอย่างไร?**
> **แนวคำตอบ:** วงจร `INPUT_PULLUP` จะมีตัวต้านทานภายในต่อดึงขาอินพุตเข้ากับแรงดันไฟเลี้ยง 3.3V ทำให้ขณะยังไม่กดปุ่ม ขาพินจะอ่านค่าลอจิกเป็น **HIGH (3.3V)** และเมื่อกดปุ่ม ขาพินจะถูกดึงลงกราวด์ (GND) ทำให้อ่านค่าลอจิกเป็น **LOW (0V)** จึงช่วยป้องกันภาวะสัญญาณลอย (Floating State)

**คำถามที่ 2: ปัญหา Contact Bouncing คืออะไร และการใช้ `millis()` ทำ Software Debounce มีข้อดีกว่าการใช้ `delay()` อย่างไร?**
> **แนวคำตอบ:** Contact Bouncing คือการที่หน้าสัมผัสโลหะของสวิตช์เด้งสั่นไปมาหลายครั้งในชั่วไม่กี่มิลลิวินาทีก่อนจะแตะสนิท ทำให้ไมโครคอนโทรลเลอร์เข้าใจผิดว่ามีการกดปุ่มซ้ำหลายครั้ง การแก้ปัญหาด้วย `millis()` (Non-blocking Debounce) ช่วยให้ระบบสามารถหน่วงเวลาตรวจสอบสัญญาณให้นิ่งได้โดยที่ CPU ไม่ถูกบล็อกการทำงาน จึงสามารถประมวลผลเซ็นเซอร์หรือคำสั่งอื่นๆ ใน `loop()` ต่อไปได้อย่างต่อเนื่อง ไม่สะดุดเหมือนการใช้ `delay()`
