โจทย์ท้าทายการทดลอง (The Grand Industrial IoT Node Challenge)

โจทย์: ให้นักศึกษาพัฒนาและทดสอบระบบ Industrial Modular IoT Node ร่วมกับหน้าเว็บ WebConfig Portal (config.html) และแดชบอร์ด PWA โดยปฏิบัติดังนี้:

  • 1. การตั้งค่าผ่าน WebConfig Portal (Dynamic Reconfiguration): เข้าใช้งานหน้า /config.html และทดลองปรับเปลี่ยนพารามิเตอร์ (เช่น เปลี่ยนพินรีเลย์พัดลมจาก 5 เป็น 19 หรือแก้ไขชื่ออุปกรณ์) และกดบันทึก ตรวจสอบว่าระบบเขียนไฟล์ /config.json และรีบูตบอร์ดเพื่อใช้การตั้งค่าใหม่สำเร็จ
  • 2. การทดสอบ Auto MAC-Based Topics Isolation: ตรวจสอบบนหน้าจอ OLED หรือ Serial Monitor ว่า Topic ที่ ESP32 ใช้งานเป็น Topic ประจำบอร์ด (เช่น esp-node/<MAC>/state) และสามารถ Publish/Subscribe ข้อมูลได้โดยไม่ชนกับกลุ่มเพื่อนในห้องปฏิบัติการ

ทฤษฎีที่เกี่ยวข้อง: การพัฒนาระบบ IoT เกรดอุตสาหกรรม (WebConfig & Auto MAC)

1.1 สถาปัตยกรรมการแยกหน้าเว็บ Dashboard และ WebConfig Portal

ในการพัฒนาอุปกรณ์ IoT ทางอุตสาหกรรม การฝังชื่อ Wi-Fi, รหัสผ่าน หรือหมายเลขขาพินลงในซอร์สโค้ดโดยตรง (Hardcoding) จะทำให้ไม่สามารถนำบอร์ดไปติดตั้งในพื้นที่อื่นได้โดยไม่ต่อคอมพิวเตอร์เพื่อแฟลชโปรแกรมใหม่

การแก้ไขด้วย Dynamic WebConfig: แยกหน้าเว็บออกเป็น 2 ส่วน:

  • Main Dashboard (/index.html): หน้าจอหลักสำหรับผู้ใช้งานทั่วไป มอนิเตอร์ค่าเซ็นเซอร์และกดเปิด-ปิดรีเลย์
  • WebConfig Portal (/config.html): หน้าจอสำหรับช่างเทคนิคหรือผู้ดูแลระบบ เพื่อปรับเปลี่ยนพินฮาร์ดแวร์และค่าเครือข่าย แล้วบันทึกเป็น /config.json ลงใน LittleFS

2.1 การสร้าง Unique Topic ด้วย Device MAC Address

เมื่ออุปกรณ์หลายร้อยตัวเชื่อมต่อไปยัง Cloud MQTT Broker เดียวกัน หากใช้ Topic พื้นฐานเหมือนกัน เช่น home/fan/cmd ทุกโหนดจะได้รับคำสั่งเดียวกันและแย่ง Client ID กันจนเกิดอาการหลุดเชื่อมต่อ (Client Collision Loop)

// ดึง MAC Address ของชิป Wi-Fi และตัดเครื่องหมายโคลอน (:)
String rawMac = WiFi.macAddress();
rawMac.replace(":", "");
String subTopic = "esp-node/" + rawMac + "/control/cmd";
String pubTopic = "esp-node/" + rawMac + "/state";

กลไกนี้ทำให้แต่ละโหนดมีหัวข้อรับ-ส่งข้อมูลเฉพาะตัวที่ไม่ซ้ำกับโหนดอื่นในโลก (Globally Unique) อย่างแท้จริง

3.1 ระบบกู้คืนค่าโรงงานฉุกเฉิน (Factory Reset via Long-Press)

หากผู้ใช้ตั้งค่า Wi-Fi หรือพินฮาร์ดแวร์ผิดพลาดจนบอร์ดค้างหรือไม่สามารถเข้าหน้าเว็บได้ ระบบมีกลไกตรวจสอบการกดปุ่ม Flash (GPIO 0) ค้างไว้ ≥ 3 วินาที:

if (digitalRead(RESET_PIN) == LOW) {
  if (pressStart == 0) pressStart = millis();
  if (millis() - pressStart >= 3000) {
    LittleFS.remove("/config.json"); // ลบไฟล์คอนฟิก
    ESP.restart(); // รีบูตเข้าสู่โหมดค่าเริ่มต้นโรงงาน
  }
}

4.1 Fallback Captive Portal AP Mode (192.168.4.1)

เมื่อบอร์ดพยายามต่อ Wi-Fi แต่ไม่สำเร็จภายใน 15-20 วินาที บอร์ดจะสลับเข้าสู่โหมด WIFI_AP โดยอัตโนมัติ พร้อมรัน DNS Server เพื่อดักจับทุกคำขอของเบราว์เซอร์ให้เปิดหน้า http://192.168.4.1/config.html ทันทีที่เชื่อมต่อ Wi-Fi ของบอร์ด

5.1 การจัดการไฟล์ด้วย LittleFS และ ArduinoJson

LittleFS คือระบบไฟล์บน SPI Flash Memory ของ ESP32/ESP8266 ที่มีระบบ Wear-Leveling ป้องกันหน่วยความจำเสื่อมสภาพจากการเขียนซ้ำ:

// ตัวอย่างการบันทึก JSON Config ลง Flash:
File file = LittleFS.open("/config.json", "w");
serializeJson(doc, file);
file.close();

6.1 Dynamic Automation Rules & Multi-Sensor Ecosystem

ในเฟิร์มแวร์เวอร์ชันอัปเกรดล่าสุด รองรับระบบ Dynamic Automation Rules Binding ซึ่งสามารถเลือกผูกตัวแปรเซ็นเซอร์ (Sensor Source) เข้ากับรีเลย์แต่ละช่องได้อย่างอิสระผ่าน WebConfig:

  • แหล่งข้อมูลเซ็นเซอร์ที่รองรับ: อุณหภูมิ/ความชื้น DHT (temp, hum), ความชื้นในดิน (soil), ก๊าซ/ควัน (gas), ความเข้มแสง (ldr), อุณหภูมิน้ำ (ds18b20), สภาพอากาศ BME280 (bme_temp, bme_hum, bme_press)
  • เงื่อนไขเปรียบเทียบ (Operator): มากกว่า (>) หรือ น้อยกว่า (<) พร้อมค่า Hysteresis ป้องกันรีเลย์ตัด-ต่อถี่เกินไป (Chattering Protection)
  • ระบบ MQTT Prefix Namespace: รองรับตัวแปร topicPrefix (ค่าเริ่มต้น: allarm-iot) เพื่อแบ่งกลุ่มหรือแยกโปรเจกต์ระดับองค์กร
