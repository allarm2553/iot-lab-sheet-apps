วัตถุประสงค์การเรียนรู้

  • เข้าใจความแตกต่างระหว่าง HTTP Polling (Request-Response) และ WebSockets (Full-Duplex Port 81)
  • สามารถสร้าง WebSocketsServer บน ESP32 / ESP8266 เพื่อรับส่งข้อมูลแบบ Real-time ร่วมกับ ArduinoJson
  • สามารถส่งคำสั่งควบคุมรีเลย์พัดลม และกระจายข้อมูลเซ็นเซอร์ (Broadcast) ไปยังทุก Web Browser ที่เชื่อมต่ออยู่พร้อมกัน
  • สามารถประยุกต์ใช้ Hysteresis Control ปรับเกณฑ์อุณหภูมิผ่าน Slider บนหน้าเว็บได้แบบเรียลไทม์

เนื้อหาทฤษฎี: Local WebSockets & JSON Real-time Communication

1.1 สถาปัตยกรรม WebSockets vs HTTP Polling

HTTP Polling: ฝั่งไคลเอนต์ต้องส่ง HTTP Request ไปยังเซิร์ฟเวอร์ทุกๆ 1-2 วินาที พร้อมส่ง Header ขนาดใหญ่ (หลายร้อยไบต์) ซ้ำๆ สิ้นเปลืองแบนด์วิดท์ และเกิดความหน่วง (Latency) สูง

WebSockets (Port 81): ทำการ Upgrade โปรโตคอลจาก HTTP เป็น TCP Full-Duplex Connection ค้างไว้เพียงครั้งเดียว ทำให้ทั้งเซิร์ฟเวอร์และไคลเอนต์ส่งข้อความหากันได้ทันทีแบบสองทาง (Bi-directional) ด้วย Overhead ของเฟรมข้อมูลเพียง 2-6 ไบต์เท่านั้น

HTTP Polling: Client --- [Request + Header] ---> Server ---> [Response] (ต้องต่อใหม่ทุกครั้ง)
WebSocket : Client <====== [ Persistent Full-Duplex TCP Tunnel ] ======> Server (Real-time)

2.1 การเข้ารหัสและถอดรหัส JSON Payload

การแลกเปลี่ยนข้อมูลผ่าน WebSocket นิยมใช้โครงสร้าง JSON ร่วมกับไลบรารี ArduinoJson v7:

// 1. การสร้าง JSON ส่งออก (Serialization):
JsonDocument doc;
doc["temp"] = 28.5;
doc["humidity"] = 65.0;
doc["fan"] = true;
String msg;
serializeJson(doc, msg);
webSocket.broadcastTXT(msg);

// 2. การรับและถอดรหัส JSON (Deserialization):
deserializeJson(doc, payload, length);
if (doc["action"] == "toggle_fan") { digitalWrite(5, doc["value"]); }

3.1 การกระจายข้อมูล (Broadcast) และ Event Handling

ฟังก์ชัน webSocketEvent(num, type, payload, length) จะถูกเรียกทำงานแบบ Event-driven ตามเหตุการณ์ที่เกิดขึ้น:

  • WStype_CONNECTED: มีไคลเอนต์ใหม่เชื่อมต่อเข้ามา (ส่งค่าสถานะเริ่มต้นกลับไปทันที)
  • WStype_DISCONNECTED: ไคลเอนต์ตัดการเชื่อมต่อ
  • WStype_TEXT: ได้รับข้อความตัวอักษร JSON จากไคลเอนต์
  • webSocket.broadcastTXT(): ส่งข้อความหาทุก Web Browser ที่เชื่อมต่ออยู่พร้อมกันทันที

เมื่อไคลเอนต์ส่งข้อความผ่านท่อ WebSocket (Port 81) จะใช้รูปแบบ JSON Event Payload ดังนี้:

วัตถุประสงค์ ข้อความที่ต้องพิมพ์ใน Message Box / ws.send() ผลลัพธ์บนไมโครคอนโทรลเลอร์
สั่งเปิดพัดลม {"action": "toggle_fan", "value": true} รีเลย์พัดลม GPIO 5 ON, broadcast สถานะกลับทุกหน้าจอ
สั่งปิดพัดลม {"action": "toggle_fan", "value": false} รีเลย์พัดลม GPIO 5 OFF, broadcast สถานะกลับทุกหน้าจอ
ปรับเกณฑ์อุณหภูมิ {"threshold": 32.5} หรือ {"action": "set_threshold", "value": 32.5} อัปเดต tempThreshold = 32.5 คำนวณ Hysteresis ทันที
สั่งเปิดปั๊มหมอก {"action": "toggle_mist", "value": true} รีเลย์ปั๊มหมอก GPIO 23 ON

⚠️ ข้อควรระวังเรื่องไวยากรณ์ JSON (JSON Syntax Rules):

  • Key และ String ต้องอยู่ในเครื่องหมาย Double Quotes "..." เสมอ
  • ค่า Boolean ต้องพิมพ์ true หรือ false (ตัวพิมพ์เล็ก ไม่มีเครื่องหมายคำพูด)
  • ค่าตัวเลขทศนิยม เช่น 32.5 ส่งตรงได้เลยโดยไม่ต้องใส่เครื่องหมายคำพูด
