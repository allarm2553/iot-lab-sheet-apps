# ⚡ ใบงานที่ 4: การส่งข้อมูลสองทางแบบเรียลไทม์ (Local WebSockets)

คู่มือการทดลองสร้างระบบควบคุมและแสดงผลแบบสองทาง (Full-Duplex Communication) ระหว่างหน้าเว็บแดชบอร์ดกับไมโครคอนโทรลเลอร์ ESP32 / ESP8266 ผ่านโปรโตคอล **WebSockets (Port 81)** ร่วมกับการแลกเปลี่ยนข้อมูลแบบ **JSON**

---

## 🎯 วัตถุประสงค์ (Objectives)

1. เข้าใจความแตกต่างระหว่าง **HTTP Polling (Request-Response)** และ **WebSockets (Event-Driven Full-Duplex)**
2. สามารถสร้าง **WebSocketsServer (Port 81)** บนไมโครคอนโทรลเลอร์เพื่อรับส่งข้อมูลกับเว็บบราวเซอร์ได้แบบเรียลไทม์
3. สามารถเข้ารหัสและถอดรหัสข้อความ JSON ผ่านไลบรารี `ArduinoJson`
4. สามารถควบคุมเปิด-ปิดรีเลย์ และปรับค่าเกณฑ์อุณหภูมิ (Temperature Threshold) จากสไลเดอร์บนหน้าเว็บ พร้อมกระจายข้อมูลเซ็นเซอร์ (Broadcast) ไปยังทุกบราวเซอร์ที่เปิดอยู่พร้อมกัน

---

## 🔌 การต่อวงจรและพินฮาร์ดแวร์ (Hardware Pinouts)

| อุปกรณ์ | บอร์ด ESP32 (IPST-WiFi) | บอร์ด ESP8266 (AX-WiFi) | คำอธิบาย |
| :--- | :--- | :--- | :--- |
| **DHT11 Sensor** | `GPIO 33` | `GPIO 2` (`D4`) | อุณหภูมิและความชื้น |

| **Mist Relay** | `GPIO 23` | `GPIO 16` (`D0`) | รีเลย์พ่นหมอก |
| **Push Button** | `GPIO 0` | `GPIO 0` (`D3`) | สลับสถานะรีเลย์บนบอร์ด |

### 2. คำถามสรุปผลการทดลอง (Review Questions)

**คำถามที่ 1: การใช้ WebSocket มีประสิทธิภาพเหนือกว่าการใช้ HTTP Polling ในงานควบคุมและติดตามผลแบบเรียลไทม์อย่างไร?**
> **แนวคำตอบ:** HTTP Polling ไคลเอนต์ต้องส่ง Request พร้อม HTTP Header ขนาดใหญ่ซ้ำๆ ไปยังเซิร์ฟเวอร์ทุกๆ 1–2 วินาที ซึ่งสิ้นเปลืองแบนด์วิดท์และทำให้เกิด Latency สูง ในขณะที่ WebSocket จะสร้างการเชื่อมต่อค้างไว้แบบ Persistent TCP Connection เพียงครั้งเดียว ทำให้สามารถส่งข้อมูลแบบสองทาง (Full-Duplex) ได้ทันทีเมื่อมีอีเวนต์เกิดขึ้น (Event-driven) ช่วยลด Overhead ของเครือข่ายและให้การตอบสนองที่รวดเร็วระดับมิลลิวินาที

**คำถามที่ 2: โครงสร้างข้อมูลแบบ JSON มีประโยชน์อย่างไรในการสื่อสารระหว่างไมโครคอนโทรลเลอร์กับ Web App?**
> **แนวคำตอบ:** JSON (JavaScript Object Notation) เป็นรูปแบบข้อความที่มีโครงสร้างแบบ Key-Value Pair ที่มนุษย์อ่านเข้าใจง่ายและคอมพิวเตอร์ประมวลผลได้เร็ว สามารถรวมข้อมูลเซ็นเซอร์หลายค่า (เช่น อุณหภูมิ, ความชื้น, สถานะรีเลย์) ไว้ในก้อนข้อความเดียวกัน ทำให้ทั้งฝั่ง C++ (ผ่าน ArduinoJson) และฝั่ง JavaScript (ผ่าน JSON.parse) สามารถแยกดึงข้อมูลไปใช้งานได้อย่างถูกต้องแม่นยำ
