เนื้อหาทฤษฎี: Wi-Fi Modes, Network Parameters, Status Enum & Event-Driven Architecture

1.1 โหมดการทำงานของโมดูล Wi-Fi (Wi-Fi Operational Modes)

ชิปไมโครคอนโทรลเลอร์ ESP32 และ ESP8266 บรรจุตัวรับส่งสัญญาณวิทยุมาตรฐาน IEEE 802.11 b/g/n (ย่านความถี่ 2.4 GHz) ซึ่งสามารถกำหนดโหมดการทำงานผ่านคำสั่ง WiFi.mode() ได้ดังนี้:

  • Station Mode (WIFI_STA): บอร์ดทำหน้าที่เป็นลูกข่าย (Client/Station) ไปเกาะเชื่อมต่อกับ Access Point หรือ Wi-Fi Router หลัก เพื่อขอรับหมายเลข IP ผ่าน DHCP และส่งข้อมูลขึ้นอินเทอร์เน็ต
  • Access Point Mode (WIFI_AP): บอร์ดทำหน้าที่เป็นจุดกระจายสัญญาณ Wi-Fi ของตัวเอง (Hotspot) ให้คอมพิวเตอร์หรือมือถือเข้ามาเชื่อมต่อโดยตรง (เช่น ตั้งค่า IP เริ่มต้นเป็น 192.168.4.1)
  • Dual Mode (WIFI_AP_STA): บอร์ดเปิดใช้งานทั้งโหมด AP และ STA พร้อมกัน นิยมใช้ในระบบ **Wi-Fi Provisioning / Captive Portal** เพื่อให้ผู้ใช้เกาะ Hotspot มาตั้งค่า SSID/Password ของบ้าน แล้วบอร์ดสั่งสแกนหาเครือข่ายไปพร้อมกัน
  • Wi-Fi Off (WIFI_OFF): ปิดภาคส่งสัญญาณวิทยุทั้งหมดเพื่อประหยัดพลังงาน เหมาะสำหรับงานใช้แบตเตอรี่และระบบ Deep Sleep

2.1 การสแกนหาเครือข่าย, ค่า RSSI และความปลอดภัย (Security Types)

ฟังก์ชัน WiFi.scanNetworks() ทำหน้าที่สั่งให้ภาครับสัญญาณกวาดหาคลื่นความถี่ 2.4 GHz ทั้ง 13 ช่องสัญญาณ (Channels 1–13) เพื่อเก็บข้อมูลเครือข่ายที่อยู่รอบตัว:

  • SSID (Service Set Identifier): ชื่อของเครือข่าย Wi-Fi ที่ค้นพบ
  • Channel (ช่องสัญญาณ 1–13): ย่านความถี่กลาง 2412 – 2472 MHz เพื่อหลีกเลี่ยงการกวนกันของคลื่น
  • Security / Encryption Type: มาตรฐานการเข้ารหัสความปลอดภัย เช่น OPEN (ไม่มีรหัส), WEP, WPA_PSK, WPA2_PSK, และ WPA3_SAE

2.2 หน่วยวัดความแรงสัญญาณ RSSI (dBm)

RSSI (Received Signal Strength Indicator) มีหน่วยเป็น dBm (Decibel-milliwatts) เป็นการเปรียบเทียบกำลังงานที่รับได้กับกำลังส่ง 1 มิลลิวัตต์ตามสเกลลอการิทึม สัญญาณวิทยุมีกำลังต่ำมากในระดับไมโครวัตต์ จึงแสดงผลเป็นค่าติดลบเสมอ:

• RSSI >= -50 dBm : สัญญาณดีเยี่ยม (Excellent Signal - ใกล้ Router มาก)
• RSSI >= -65 dBm : สัญญาณดี เหมาะสำหรับงาน IoT ส่งข้อมูลต่อเนื่อง (Good Signal)
• RSSI >= -75 dBm : สัญญาณระดับปานกลาง/พอใช้ (Fair Signal)
• RSSI < -80 dBm : สัญญาณอ่อนมาก อาจเกิด Packet Loss หรือหลุดบ่อย (Poor Signal)

3.1 พารามิเตอร์สำคัญของระบบเครือข่าย (Network Parameters)

  • WiFi.localIP(): หมายเลข IP Address ประจำตัวบอร์ดบนวง LAN (Layer 3)
  • WiFi.subnetMask() & WiFi.gatewayIP(): ซับเน็ตมาสก์และไอพีเราเตอร์สำหรับชี้ทางออกอินเทอร์เน็ต
  • WiFi.dnsIP(): เซิร์ฟเวอร์ DNS สำหรับแปลงชื่อ Domain (เช่น 8.8.8.8)
  • WiFi.macAddress(): หมายเลขประจำตัวฮาร์ดแวร์ชิป (Layer 2 MAC) ไม่ซ้ำกันในโลก เหมาะใช้เป็น Unique Device ID บนระบบคลาวด์
  • WiFi.BSSIDstr(): หมายเลข MAC Address ของ Access Point ที่บอร์ดเชื่อมต่ออยู่

3.2 ตารางค่าสถานะการเชื่อมต่อ (wl_status_t Enum)

ฟังก์ชัน WiFi.status() ส่งคืนค่ารหัสตัวเลขบอกสถานะปัจจุบันของ Wi-Fi Interface:

• WL_CONNECTED (3) : เชื่อมต่อสำเร็จและได้รับ IP เรียบร้อย
• WL_DISCONNECTED (6) : หลุดการเชื่อมต่อ หรือถูกตัดการเชื่อมต่อจาก AP
• WL_CONNECT_FAILED (4) : เชื่อมต่อล้มเหลว (เช่น ใส่รหัสผ่านผิด)
• WL_NO_SSID_AVAIL (1) : ไม่พบชื่อ SSID เป้าหมายในระยะสัญญาณ
• WL_CONNECTION_LOST (5) : สัญญาณขาดหายระหว่างเชื่อมต่อ
• WL_IDLE_STATUS (0) : อยู่ในสถานะพัก / กำลังสลับโหมด
• WL_SCAN_COMPLETED (2) : สแกนหาเครือข่ายเสร็จสมบูรณ์
• WL_NO_SHIELD (255) : ไม่พบโมดูล Wi-Fi หรือฮาร์ดแวร์ขัดข้อง

4.1 เปรียบเทียบ: Status Polling ใน loop() vs Event-Driven Callback

ในการกู้คืนการเชื่อมต่อเมื่อสัญญาณ Wi-Fi หลุด มี 2 แนวทางหลัก ซึ่งมีความแตกต่างกันอย่างมากในแง่ประสิทธิภาพและความเสถียร:

มิติการเปรียบเทียบ 🔴 Status Polling ใน loop() 🟢 Event-Driven Callback
สถาปัตยกรรม Synchronous Polling (คอยถามซ้ำๆ) Asynchronous / Interrupt-driven (แจ้งเมื่อมีเหตุ)
ภาระ CPU สิ้นเปลืองรอบ CPU ในการเรียก WiFi.status() ซ้ำๆ Zero CPU Overhead ใน Main Loop ทำงานเมื่อสถานะเปลี่ยนจริง
ความเร็วในการกู้คืน ช้ากว่า ขึ้นกับรอบเวลา (เช่น ทุก 5-10 วินาที) หรือติด Delay รวดเร็วทันทีระดับ Real-time (หลักมิลลิวินาที)
ความเสี่ยงระบบค้าง เสี่ยงสูง หากติด while หรือ delay งานหลักจะสะดุด ปลอดภัย 100% (Non-blocking) ทำงานใน System Background
ความสะอาดของโค้ด โค้ดใน loop() ปะปนระหว่างงานควบคุมกับ Network โค้ดใน loop() สะอาดมาก แยกส่วน Network ไว้ใน setup()
การนำไปใช้งานจริง เหมาะสำหรับศึกษาพื้นฐานเบื้องต้น มาตรฐานสำหรับอุปกรณ์ IoT เชิงพาณิชย์ (Production)

4.2 ตัวอย่างโค้ดเปรียบเทียบการใช้งานจริง

// 🟢 แบบ Event-Driven: ลงทะเบียนใน setup() แล้วปล่อยให้ loop() ทำงานเซนเซอร์ได้อย่างอิสระ
#if defined(ESP32)
WiFi.onEvent([](WiFiEvent_t event, WiFiEventInfo_t info) {
  if (event == ARDUINO_EVENT_WIFI_STA_DISCONNECTED) {
    Serial.println("[Event] Wi-Fi หลุด! สั่ง Reconnect ใน Background ทันที...");
    WiFi.reconnect();
  } else if (event == ARDUINO_EVENT_WIFI_STA_GOT_IP) {
    Serial.println("[Event] ได้รับ IP: " + WiFi.localIP().toString());
  }
});
#elif defined(ESP8266)
WiFiEventHandler dHandler = WiFi.onStationModeDisconnected([](const WiFiEventStationModeDisconnected& e) {
  WiFi.reconnect();
});
#endif
WiFi.setAutoReconnect(true);

5.1 รูปแบบคำสั่งควบคุมและตรวจเช็ค Wi-Fi ผ่าน Message Box

นักศึกษาสามารถส่งคำสั่งทดสอบผ่าน Serial Monitor Input Box (Baud rate 115200) หรือกล่องข้อความคำสั่งบนเว็บแอป เพื่อควบคุมและทดสอบกระบวนการเชื่อมต่อเครือข่าย:

วัตถุประสงค์ คำสั่งที่ต้องพิมพ์ใน Message Box การตอบสนองของไมโครคอนโทรลเลอร์
สั่งสแกนเครือข่ายรอบตัว SCAN_WIFI สั่ง WiFi.scanNetworks() แล้วส่งตาราง SSID, RSSI, Channel กลับมา
สั่งเชื่อมต่อ Access Point CONNECT:MySSID,MyPassword เรียก WiFi.begin("MySSID", "MyPassword")
อ่านพารามิเตอร์ IP & MAC GET_NETWORK_INFO ส่งคืน IP Address, Subnet, Gateway, DNS, MAC Address
จำลองการตัดการเชื่อมต่อ DISCONNECT_WIFI สั่ง WiFi.disconnect() เพื่อทดสอบระบบ Event-driven Auto-reconnect
// ตัวอย่างการแยกคำสั่ง Wi-Fi จาก Serial:
if (Serial.available()) {
  String cmd = Serial.readStringUntil('\n');
  cmd.trim();
  if (cmd == "SCAN_WIFI") {
    int n = WiFi.scanNetworks();
    Serial.printf("[SCAN] พบเครือข่ายทั้งหมด %d วง\n", n);
  } else if (cmd == "DISCONNECT_WIFI") {
    WiFi.disconnect();
  }
}
