# 🌡️ ใบงานที่ 1: การอ่านค่าเซ็นเซอร์และการควบคุมเอาต์พุต (GPIO, ADC & Relays)

คู่มือการทดลองควบคุมไมโครคอนโทรลเลอร์ ESP32 / ESP8266 ในการอ่านค่าเซ็นเซอร์อุณหภูมิและความชื้น (DHT11), ตัวต้านทานปรับค่าได้ (Potentiometer / ADC) และการสั่งงานรีเลย์ควบคุมพัดลมและหัวพ่นหมอก พร้อมระบบความปลอดภัยและการจัดการข้อผิดพลาด (Fault-Tolerant & Fail-Safe Integration)

---

## 🎯 วัตถุประสงค์ (Objectives)

1. สามารถกำหนดโหมดของขา GPIO เป็น `INPUT` และ `OUTPUT` ได้อย่างถูกต้อง และเข้าใจความแตกต่างของ Active-HIGH กับ Active-LOW
2. สามารถอ่านค่าความต่างศักย์ไฟฟ้าแบบแอนะล็อกผ่านตัวแปลงสัญญาณ **ADC (Analog-to-Digital Converter)** และแปลงเป็นเปอร์เซ็นต์ (0–100%) โดยไม่เกิดข้อผิดพลาด Integer Division
3. สามารถติดต่อสื่อสารและอ่านข้อมูลอุณหภูมิและความชื้นสัมพัทธ์จากเซ็นเซอร์ **DHT11** พร้อมตรวจจับความผิดพลาดด้วยฟังก์ชัน `isnan()`
4. เข้าใจหลักการควบคุมแบบ **Hysteresis (ส่วนต่างของจุดตัด)** เพื่อป้องกันปัญหารีเลย์เปิด-ปิดถี่เกินไป (Relay Clicking / Chatter)
5. สามารถออกแบบกลไก **Fail-Safe Protection** เพื่อตัดการทำงานของอุปกรณ์กำลังสูงเมื่อเซ็นเซอร์หลุดหรือไม่ตอบสนอง

## 🛠️ ตารางการตรวจวินิจฉัยและแก้ปัญหาข้อผิดพลาด (Troubleshooting Guide)

| ปัญหาที่พบบ่อย | อาการ (Symptoms) | สาเหตุที่แท้จริง (Root Cause) | แนวทางแก้ไข (Solution) |
| :--- | :--- | :--- | :--- |
| **DHT11 อ่านค่าเป็น NaN** | Serial พิมพ์ `nan` หรือ `Failed to read` | • อ่านค่าเร็วกว่า 2 วินาที<br>• สาย DATA หลุด/หลวม<br>• ไฟเลี้ยงไม่พอ | • ใช้ `millis()` กำหนดรอบอ่าน $2000\text{ms}+$\<br>• ตรวจสอบสายต่อขา GPIO 33<br>• ดักจับด้วย `isnan()` และตัดโหลดเข้า Safe State |
| **เปอร์เซ็นต์ ADC ได้ 0.0% เสมอ** | บิดตัวต้านทานแล้วค่าไม่เปลี่ยน | เกิด **Integer Division** ในสูตรคำนวณ เช่น `(raw / 4095) * 100` | เปลี่ยนตัวหารเป็น `4095.0` หรือใช้ `((float)raw / 4095.0) * 100.0` |
| **รีเลย์ทำงานกลับด้าน (Inverted)** | เปิดเครื่องแล้วพัดลมหมุนทันที | โมดูลรีเลย์เป็นแบบ **Active-LOW** | กำหนด `#define RELAY_ON LOW` และ `#define RELAY_OFF HIGH` |
| **รีเลย์ตัด-ต่อถี่ (Relay Chatter)** | ได้ยินเสียงรีเลย์กระตุกถี่ๆ เมื่ออุณหภูมิใกล้ 30°C | ไม่มีช่วง Deadband (ใช้เงื่อนไข `>` จุดเดียว) | เพิ่มตรรกะ **Hysteresis** (เปิดเมื่อ $\ge 30.0^\circ\text{C}$, ปิดเมื่อ $\le 29.5^\circ\text{C}$) |

### 3. คำถามท้ายการทดลอง & การวิเคราะห์ข้อผิดพลาด (Review Questions)

**คำถามที่ 1: [Spot the Bug: ADC Integer Division] นักศึกษาคนหนึ่งเขียนโค้ด `int raw = analogRead(36); float percent = (raw / 4095) * 100;` แต่ค่าที่ได้แสดงเป็น `0.0%` เสมอแม้จะหมุนปรับค่า VR จงวิเคราะห์ว่าเกิดจากสาเหตุใด และต้องแก้ไขโค้ดอย่างไรให้ถูกต้อง?**
> **แนวคำตอบ:** 
> - **สาเหตุ:** ตัวแปร `raw` และค่าคงที่ `4095` ถูกกำหนดเป็นชนิดข้อมูลจำนวนเต็ม (`int`) ทั้งคู่ คอมไพเลอร์จึงประมวลผลแบบ **Integer Division** ซึ่งทำการปัดเศษทศนิยมทิ้งทันที ทำให้เมื่อ `raw` มีค่าน้อยกว่า 4095 ผลลัพธ์จากการหารจะเป็น `0` เสมอ เมื่อนำไปคูณ 100 จึงได้ `0.0%`
> - **วิธีแก้:** บังคับให้เกิดการคำนวณแบบ Floating-point โดยเปลี่ยนตัวหารเป็นทศนิยม `4095.0` หรือใช้ Type Casting เป็น `((float)raw / 4095.0) * 100.0`

**คำถามที่ 2: [Relay Control & Inverted Logic] เหตุใดเราจึงต้องใช้โมดูลรีเลย์ในการขับพัดลม/ปั๊มน้ำแทนการต่อตรงกับขา GPIO และหากโมดูลรีเลย์ที่ใช้เป็นชนิด Active-LOW เราต้องเขียนคำสั่งควบคุมให้เปิดและปิดโหลดอย่างไร?**
> **แนวคำตอบ:** 
> - ขา GPIO ของ ESP32 จ่ายกระแสไฟฟ้าได้สูงสุดเพียงประมาณ 12–20mA ที่ 3.3V ซึ่งไม่สามารถจ่ายพลังงานให้แก่มอเตอร์พัดลมหรือปั๊มน้ำ (ต้องการ 100mA–1A+ ที่ 5V/12V/220V) ได้โดยตรง นอกจากนี้โมดูลรีเลย์ยังมี Optocoupler และ Diode ป้องกันแรงดันเหนี่ยวนำย้อนกลับ (Back EMF) จากมอเตอร์ไม่ให้ทำลายชิปไมโครคอนโทรลเลอร์
> - สำหรับโมดูลรีเลย์แบบ **Active-LOW**:
>   - คำสั่งสั่งเปิดโหลด (ทำงาน): `digitalWrite(RELAY_PIN, LOW);`
>   - คำสั่งสั่งปิดโหลด (หยุดทำงาน): `digitalWrite(RELAY_PIN, HIGH);`

**คำถามที่ 3: [Fail-Safe Design: Sensor Disconnection] หากสายสัญญาณ DATA ของเซ็นเซอร์ DHT11 หลุดระหว่างทำงาน โค้ดที่ไม่มีการดักจับค่าด้วยฟังก์ชัน `isnan()` จะส่งผลกระทบต่อการตัดสินใจของรีเลย์อย่างไร และแนวทางการเขียนระบบความปลอดภัย (Fail-Safe Action) ที่ดีควรเป็นอย่างไร?**
> **แนวคำตอบ:**
> - หากสายหลุด ฟังก์ชัน `readTemperature()` จะคืนค่า `NaN` (Not a Number) เมื่อนำค่า NaN ไปเปรียบเทียบในเงื่อนไข `if (temperature > 30.0)` ผลลัพธ์จะให้ค่า `false` เสมอ ส่งผลให้ระบบสั่งปิดพัดลมหรือไม่ยอมเปิดพัดลมระบายความร้อนแม้ว่าอุณหภูมิจริงในห้องหรือฟาร์มจะพุ่งสูงจนเกิดความเสียหาย
> - **แนวทาง Fail-Safe ที่ถูกต้อง:** ต้องใช้ `isnan(temp) || isnan(hum)` ตรวจสอบ หากพบข้อผิดพลาด ให้ระบบสั่ง **ตัดการทำงานของโหลดทั้งหมดทันที (Safe State)** และส่งสัญญาณแจ้งเตือน (Hardware Alert เช่น กระพริบไฟ LED หรือส่งเสียงเตือน) ไปยังผู้ควบคุม
