วัตถุประสงค์การทดลอง

  • เข้าใจความแตกต่างและการทำงานของเมธอด HTTP GET (อ่านค่า) และ HTTP POST (ส่งคำสั่ง)

ศึกษาโค้ดต่อไปนี้และค้นหาคำตอบเพื่อนำมาเติมในช่องว่างให้สมบูรณ์:

#include <Arduino.h>
#include <WiFi.h>
#include <WebServer.h>
#include <ArduinoJson.h>
#include <DHT.h>

WebServer server(80);
DHT dht(33, DHT11);
bool relayState = false;

// 1. ฟังก์ชันส่งค่าเซ็นเซอร์กลับเป็น JSON (HTTP GET)
void handleGetData() {
  JsonDocument doc;
  doc["temp"] = dht.readTemperature();
  doc["humidity"] = dht.readHumidity();
  doc["relay"] = relayState;
  
  String jsonStr;
  ;
  ;
}

// 2. ฟังก์ชันรับคำสั่งควบคุมรีเลย์ (HTTP POST)
void handleSetRelay() {
  if (server.hasArg("plain")) {
    JsonDocument doc;
    ;
    if (doc["relay"].is<JsonVariant>()) {
      relayState = doc["relay"];
      digitalWrite(5, relayState ? HIGH : LOW);
    }
    server.send(200, "application/json", "{\"success\":true}");
  }
}

void setup() {
  Serial.begin(115200);
  pinMode(5, OUTPUT);
  dht.begin();
  WiFi.begin("iot_512", "iot123456");
  while (WiFi.status() != WL_CONNECTED) delay(500);

  // ลงทะเบียน REST API Endpoints
  ;
  ;

  server.begin();
}

void loop() {
  server.handleClient();
}

โจทย์ท้าทายการทดลอง (Challenge Task)

ให้นักศึกษาพัฒนาและต่อยอดโปรแกรม Web Server REST API ให้มีคุณสมบัติครบถ้วนตามระบบควบคุมจริง สอดคล้องกับไฟล์ Solution:

  1. การประมวลผล JSON Payload ใน HTTP POST: พัฒนาฟังก์ชัน handleSetRelay() ให้รองรับทั้ง {"relay": true/false} และ {"action": "toggle"} พร้อมส่งสถานะผลลัพธ์กลับในรูปแบบ JSON
  2. การแสดงผลบนจอ OLED SSD1306 (I2C): แสดงข้อมูล IP Address, อุณหภูมิ, ความชื้น, สถานะรีเลย์ (ON/OFF), และตัวนับการกดปุ่ม
  3. ระบบสวิตช์ปุ่มกดกายภาพ (GPIO 0 Debounce): เขียนตรรกะตรวจจับการกดปุ่ม SW1/FLASH เพื่อสลับสถานะรีเลย์บนบอร์ด พร้อมอัปเดตตัวนับและสะท้อนสถานะไปยัง REST API
  4. การรองรับ CORS Header: ใส่ Access-Control-Allow-Origin: * ในการตอบกลับ เพื่อให้เว็บแดชบอร์ดสามารถเรียกใช้งานได้จากทุกที่

ทฤษฎีที่เกี่ยวข้อง: HTTP REST API บนไมโครคอนโทรลเลอร์

1.1 ความแตกต่างระหว่าง HTTP GET และ POST

HTTP GET: ใช้สำหรับขออ่านข้อมูลจากเซิร์ฟเวอร์ ข้อมูลพารามิเตอร์จะแนบไปกับ URL ผ่าน Query String จึงเหมาะกับการดึงค่าเซ็นเซอร์ที่ไม่ส่งผลกระทบต่อสถานะของฮาร์ดแวร์ (Idempotent & Safe)

GET /api/data?unit=celsius HTTP/1.1

HTTP POST: ใช้สำหรับส่งชุดข้อมูล Payload ไปยังเซิร์ฟเวอร์เพื่อสั่งการหรือเปลี่ยนแปลงสถานะ (State Mutation) ข้อมูลจะถูกเก็บไว้ใน Request Body ปลอดภัยจากการถูกแคชบนบราวเซอร์

POST /api/relay HTTP/1.1
Content-Type: application/json

{"relay": true}

2.1 การพัฒนา REST API บน ESP32/ESP8266

ไมโครคอนโทรลเลอร์สามารถจำลองตนเองเป็น Web Server บนพอร์ต 80 โดยใช้ไลบรารี WebServer (ESP32) หรือ ESP8266WebServer (ESP8266) ร่วมกับ ArduinoJson ในการแลกเปลี่ยนข้อมูลแบบ Key-Value

server.on("/api/data", HTTP_GET, handleGetData);
server.on("/api/relay", HTTP_POST, handleSetRelay);

การใส่ CORS Header (Access-Control-Allow-Origin: *) มีความจำเป็นเพื่อให้หน้าเว็บภายนอกหรือ Dashboard บน Localhost สามารถส่ง fetch() ข้ามโดเมนมายังบอร์ดได้

3.1 การวิเคราะห์ปัญหา HTTP Polling

การดึงข้อมูลเซ็นเซอร์ด้วยเทคนิค HTTP Polling เว็บเบราว์เซอร์จะต้องส่ง HTTP GET Request ไปยังไมโครคอนโทรลเลอร์ซ้ำๆ ทุก 1–2 วินาที ซึ่งมีข้อจำกัด:

  • Overhead สูง: ต้องส่ง HTTP Header ขนาดใหญ่ (~500–1000 ไบต์) ไปกลับทุกรอบ
  • เปิด-ปิด TCP Connection ซ้ำๆ: ทำให้สูญเสีย RAM และเวลาในการทำ TCP 3-Way Handshake
  • Server Push ไม่ได้: บอร์ดไม่สามารถส่งข้อมูลแจ้งเตือนมาหาเว็บได้ทันทีถ้าเว็บไม่ส่งคำขอมา

เพื่อแก้ปัญหานี้ ในใบงานถัดไป (Lab 4 และ Lab 5) จะเปลี่ยนไปใช้โปรโตคอล WebSockets และ MQTT
