# 📟 ใบงานที่ 2: การแสดงผลผ่านจอ OLED SSD1306 (I2C & Multi-Sensor Dashboard)

คู่มือการทดลองเชื่อมต่อจอแสดงผล **OLED 0.96 นิ้ว SSD1306 (ความละเอียด 128x64 พิกเซล)** ผ่านการสื่อสารบัส **I2C** พร้อมนำค่าจากเซ็นเซอร์ DHT11/DHT22, Potentiometer และสถานะสวิตช์ปุ่มกดมาจัดวางแสดงผลแบบ Multi-Sensor IoT Dashboard

---

## 🎯 วัตถุประสงค์ (Objectives)

1. เข้าใจโปรโตคอลการสื่อสารแบบอนุกรม **I2C (Inter-Integrated Circuit)** ซึ่งใช้สายสัญญาณเพียง 2 เส้น ได้แก่ **SDA (Data)** และ **SCL (Clock)** พร้อมระบบระบุตัวตนด้วย **I2C Address (0x3C)**
2. เข้าใจบทบาทของ **Frame Buffer (1,024 ไบต์ใน RAM)** และคำสั่ง `display.display()` ในการส่งข้อมูลขึ้นหน้าจอแบบ Flicker-Free
3. สามารถใช้งานฟังก์ชันกราฟิกจากไลบรารี `Adafruit_GFX` (วาดแถบ Header แบบ Inverted Text, วาดเส้นแบ่ง, และสร้าง Progress Bar)
4. สามารถออกแบบและจัดวาง UI บนหน้าจอขนาด 128x64 พิกเซล ร่วมกับการใช้ **Non-blocking Timer (`millis()`)** เพื่อรีเฟรชหน้าจออย่างมีประสิทธิภาพ

## 🛠️ ตารางการตรวจวินิจฉัยและแก้ปัญหา (Troubleshooting Matrix)

| อาการที่พบ (Symptom) | สาเหตุที่แท้จริง (Root Cause) | แนวทางแก้ไข (Solution) |
| :--- | :--- | :--- |
| **`SSD1306 allocation failed`** | ต่อสาย SDA/SCL หลวม หรือระบุ I2C Address ผิด (เช่น `0x3D`) | ตรวจสอบการต่อสายพิน I2C ให้ตรง และกำหนด Address เป็น `0x3C` |
| **โค้ดรันปกติแต่จอดำสนิท** | ลืมเรียกคำสั่ง `display.display();` หรือลืมจ่ายไฟเลี้ยง VCC 3.3V | เพิ่มคำสั่ง `display.display();` ท้ายบล็อกการวาดภาพเสมอ |
| **ตัวอักษรและภาพซ้อนทับกันเละ** | ไม่ได้ล้าง Frame Buffer ก่อนวาดภาพเฟรมใหม่ | เรียก `display.clearDisplay();` ทุกครั้งก่อนเริ่มวาดข้อมูลใหม่ |
| **ระบบหน่วง ปุ่มกดตอบสนองช้า** | สั่ง `display.display()` ทุกรอบลูป ทำให้ I2C ติดคอขวด | ใช้ Non-blocking Timer `millis()` รีเฟรชจอที่ความถี่ 2–5 Hz (200–500ms) |

### 3. คำถามท้ายการทดลอง & การวิเคราะห์ข้อผิดพลาด (Review Questions)

**คำถามที่ 1: [Spot the Bug 1: Missing Frame Buffer Flush] นักศึกษาคนหนึ่งเขียนโค้ด `setup()` และ `loop()` โดยเรียกคำสั่ง `display.clearDisplay(); display.setCursor(0,0); display.print("IoT Lab 2");` แต่ปรากฏว่าหน้าจอ OLED ดำสนิทไม่มีข้อความใดๆ ปรากฏขึ้นเลย จงวิเคราะห์ว่าขาดคำสั่งใด และอธิบายหลักการทำงานของ Frame Buffer?**
> **แนวคำตอบ:** 
> - **สาเหตุ:** ขาดคำสั่ง `display.display();`
> - **หลักการ Frame Buffer:** คำสั่ง `print()` เป็นเพียงการแก้ไขข้อมูลบิตแมพใน Frame Buffer ขนาด 1,024 ไบต์บน RAM ของไมโครคอนโทรลเลอร์เท่านั้น ข้อมูลยังไม่ได้ถูกส่งออกไปที่ตัวจอจริง จนกว่าจะมีการเรียกคำสั่ง `display.display()` เพื่อส่งข้อมูลทั้งหมดก้อนเดียวผ่านบัส I2C ไปยังชิปไดรเวอร์ SSD1306

**คำถามที่ 2: [I2C Bus Collision & Multi-device Architecture] หากในอนาคตต้องการต่อเซ็นเซอร์ตรวจวัดความดันบรรยากาศ (BMP280 - I2C) และเซ็นเซอร์วัดความเข้มแสง (BH1750 - I2C) เพิ่มเติมเข้ากับบอร์ด ESP32 จะต้องต่อสายสัญญาณอย่างไร และระบบแยกแยะอุปกรณ์แต่ละตัวได้อย่างไรโดยที่สายสัญญาณไม่ชนกัน?**
> **แนวคำตอบ:** 
> - **การต่อวงจร:** สามารถต่อสายสัญญาณ **SDA และ SCL ขนานร่วมกันเข้ากับขา GPIO 21 และ GPIO 22 ของ ESP32 ได้โดยตรง** (รวมทั้งต่อไฟเลี้ยงและกราวด์ร่วมกัน)
> - **การแยกแยะ:** ระบบ I2C ใช้การระบุตัวตนด้วย **7-bit I2C Address** ประจำตัวของแต่ละอุปกรณ์ (เช่น OLED = `0x3C`, BMP280 = `0x76`, BH1750 = `0x23`) ไมโครคอนโทรลเลอร์จะส่งไบต์แอดเดรสออกไปก่อน อุปกรณ์ที่มีแอดเดรสตระกูลนั้นเท่านั้นจึงจะตอบรับ (ACK) สัญญาณจึงไม่ชนกัน

**คำถามที่ 3: [UI/UX & Frame Rate Optimization] จงอธิบายเหตุผลว่าทำไมในการพัฒนาอุปกรณ์ IoT ทางอุตสาหกรรม เราจึงควรใช้ตัวจับเวลา Non-blocking (`millis()`) กำหนดอัตราการรีเฟรชหน้าจอ OLED (เช่น 2–5 Hz หรือทุกๆ 200–500ms) แทนการอัปเดตหน้าจอทุกรอบลูป และมีเทคนิคอย่างไรในการป้องกันปัญหา Screen Burn-in บนจอ OLED?**
> **แนวคำตอบ:** 
> - **Frame Rate Optimization:** การส่งข้อมูล 1KB ผ่าน I2C ที่ความเร็ว 100-400kHz ใช้เวลาระดับมิลลิวินาที การใช้ `millis()` ควบคุมอัตราการรีเฟรช 2–5 ครั้งต่อวินาทีช่วยลดภาระของบัส I2C ทำให้ไมโครคอนโทรลเลอร์มีเวลาเพียงพอในการประมวลผลงานสำคัญอื่นๆ เช่น การอ่านเซ็นเซอร์, การสแกนปุ่มกดแบบ Debounce, และการเชื่อมต่อ WiFi/MQTT ได้อย่างราบรื่น
> - **Burn-in Prevention:** จอ OLED มีสารอินทรีย์เปล่งแสงที่เสื่อมสภาพตามเวลาหากจุดใดสว่างแช่ค้างนานๆ เทคนิคป้องกันทำได้โดย:
>   1. **Auto-dimming / Screen Timeout:** สั่งปิดหน้าจอ (`display.ssd1306_command(SSD1306_DISPLAYOFF);`) เมื่อไม่มีการกดปุ่มเป็นเวลานาน
>   2. **Pixel Shifting:** ขยับตำแหน่งพิกัดของข้อความ $(X, Y)$ เล็กน้อย 1-2 พิกเซลเป็นระยะๆ

## 🏆 โจทย์ท้าทายการทดลอง (Lab 2 Challenge)

เขียนโปรแกรมบูรณาการนำข้อมูลทั้งหมดมาจัดวางแสดงผลบนจอ OLED 128x64 ในรูปแบบ Smart Dashboard:
1. **Header:** วาดแถบข้อความพาดหัวแบบ Inverted Text (เช่น `"IoT SMART DASHBOARD"`)
2. **DHT Readings:** แสดงค่าอุณหภูมิและความชื้น (พร้อมจัดการ NaN Error หากเซ็นเซอร์หลุด)
3. **ADC Gauge:** แสดงค่าเปอร์เซ็นต์แอนะล็อกและวาด Progress Bar กราฟิก (`drawRect` และ `fillRect`)
4. **Relay & Toggle:** แสดงสถานะเปิด/ปิดของรีเลย์ และจำนวนครั้งที่กดสวิตช์ปุ่มกด (อัปเดตทันทีเมื่อกดปุ่ม)
